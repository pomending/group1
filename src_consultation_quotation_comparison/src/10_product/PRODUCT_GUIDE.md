# 상품관리 사용 안내

기준일: 2026-11-05. 접속 주소는 `/product`이다.

## 목록과 상세

- 상품명·번호 검색, 판매 상태·단가 범위 필터와 상품명/단가/등록일/최근 수정순 정렬을 사용할 수 있다. 조건을 바꾸면 첫 페이지로 돌아간다.
- 검색도 중복 검사와 같은 기준으로 앞뒤 공백·영문 대소문자·한글 유니코드 표기를 정리해 비교한다. 상품 이름 자체는 바꾸지 않는다.
- 같은 검색창에서 상품명은 부분 일치, 상품 번호는 앞뒤 공백을 제외한 전체 일치로 찾는다. 예를 들어 `12`는 번호 12와 이름에 12가 포함된 상품을 함께 표시하며, 번호 123을 번호만으로 찾지는 않는다. 판매 상태·단가 범위·CSV에도 같은 검색 결과가 적용된다.
- 등록일은 실제 시각순으로 정렬한다. 날짜만 있는 자료는 한국 자정 기준으로 비교하며 날짜가 없거나 잘못된 자료는 최신순·오래된순 모두 마지막에 표시한다.
- 검색 결과가 없으면 **조건 초기화**로 검색·판매 상태·단가 범위를 해제할 수 있다. 정렬은 유지하고 검색칸으로 초점을 옮긴다. 상단 **초기화**는 정렬도 등록일 최신순으로 되돌린다.
- **추가 검색 조건**을 펼쳐 최소·최대 단가를 입력하면 바로 조회한다. 0원과 양 끝 금액을 포함하며 빈 경계는 제한 없음이다. 조건을 접어도 적용하고 제목에 적용 중임을 표시한다. 음수·소수·안전한 정수 범위 초과·최소가 최대보다 큰 경우에는 오류를 안내하고 조회·CSV 내보내기를 제한한다. 올바른 값으로 고치거나 초기화하면 복구된다.
- **단가 조건 해제**는 추가 검색 조건 안에 있다. 단가만 지우고 검색어·판매 상태·정렬은 유지한다. 첫 페이지로 돌아가 최소 단가 입력에 초점을 둔다. 단가 조건이 없으면 버튼을 비활성화한다.
- **최근 수정순**은 저장된 수정일의 실제 시각 내림차순이다. 수정일이 없거나 잘못된 상품은 뒤에 배치한다. 같은 시각이거나 둘 다 유효한 수정일이 없으면 기존과 같이 ID순으로 정한다. 등록일을 수정일로 대체하지 않는다.
- 목록은 10개씩 표시한다. 상단 현황은 전체 상품 기준이고 조회 건수는 검색·필터 결과 기준이다.
- 현황 카드를 누르면 판매 상태 필터가 함께 바뀌고 첫 페이지로 이동한다. 검색어·단가 범위·정렬은 유지하며 선택된 카드를 강조한다. **전체 상품** 카드는 판매 상태만 해제한다. 카드는 기본 버튼이므로 Enter·Space로도 선택할 수 있다.
- 조회 건수는 검색어·판매 상태·적용한 단가 범위와 함께 보조기기에 알린다. 실제 스크린리더의 낭독 동작은 별도 확인이 필요하다.
- 상품명을 누르면 상세 화면이 열린다. **상품 수정**으로 편집하거나 **목록으로** 돌아간다.
- 상세 상단에는 상품명·단가·판매 상태를 강조하고, 하단 **관리 정보**에는 상품 번호·등록일·수정일을 표시한다. 긴 이름은 줄바꿈하며 좁은 화면에서는 한 열로 배치한다.
- 목록으로 돌아오면 검색·정렬·페이지를 유지한다. 원래 상품 버튼이 없으면 목록 제목으로 초점을 이동한다.

## 등록·수정

화면 제목은 **상품 등록 / 상품 수정 / 상품 복사 등록**으로 구분한다. 저장 버튼은 신규·복사 등록에서 **등록 저장**, 기존 상품 수정에서 **수정 저장**으로 표시한다. 복사 준비 안내는 아직 상품이 추가되지 않은 상태이며 **등록 저장**을 눌러야 목록에 반영된다.

| 항목 | 규칙 |
|---|---|
| 상품명 | 필수, 최대 100자. 앞뒤 공백을 제거해 저장하며 영문 대소문자·동일 유니코드 표기만 다른 이름도 중복으로 처리 |
| 기본 단가 | 필수, 0 이상의 안전한 정수 |
| 판매 상태 | 판매 중 또는 판매 중지 |
| 상품 번호·등록일 | 새 상품 저장 시 자동 생성 |
| 최종 수정일 | 정보나 판매 상태가 실제로 변경될 때 갱신. 변경 없이 저장하면 기존 날짜 유지 |

- 오류는 해당 입력칸 아래에 표시하고 첫 오류 칸으로 초점을 옮긴다. 해당 값을 입력하면 안내가 해제되며 저장할 때 다시 검증한다.
- 상품명·기본 단가에 필수를 표시한다. 이름 입력 아래에는 현재 글자 수와 최대 100자 안내, 금액 아래에는 원 단위 정수 안내를 표시한다. 안내와 오류는 입력칸의 접근성 설명에도 연결한다.
- 유효한 금액 아래에는 쉼표를 넣은 미리보기(예: `12,000원`)를 표시한다. 빈 값·음수·소수·안전한 정수 범위를 넘는 값은 미리보기를 숨긴다. 입력 문자열과 저장할 숫자 형식은 바꾸지 않는다.
- 작성 중 **취소**를 누르면 변경 내용 폐기를 확인한다. 변경이 없거나 원래 입력값으로 돌아왔으면 바로 닫힌다. 새로고침·페이지 이동 전에는 필요한 내용을 저장해야 한다.
- 취소 확인 문구는 신규 등록·기존 상품 수정·복사 등록에 맞춰 구분한다. 확인을 거절하면 입력을 그대로 유지한다.
- 수정 중 같은 상품의 정보가 Context에서 변경되거나 삭제되면 저장을 차단한다. 입력은 유지되므로 필요한 내용을 확인한 뒤 취소하고 최신 상품을 다시 연다. 다른 상품의 변경은 유지하면서 저장할 수 있다.
- 수정 후에는 기존 목록 조건을 유지한다. 새로 등록한 경우에는 검색·상태·단가 필터를 해제하고 첫 페이지로 이동한다.

## 판매 상태와 날짜

- 목록과 상세의 **판매 중지/판매 재개** 버튼은 같은 확인창과 공통 수정 함수를 사용한다. 승인한 경우에만 해당 상품의 상태·수정일을 변경하며 취소·실패 시 정보를 유지한다. 상세에서는 변경 후에도 같은 상품을 보여준다. 목록 복귀 시 필터 때문에 상품이 사라질 수 있으며 원래 버튼이 없으면 목록 제목으로 초점을 이동한다.
- 목록 날짜와 상세 시각은 한국 시간(KST) 기준이다. 날짜만 저장된 자료에는 임의의 시간을 붙이지 않고, 비어 있거나 유효하지 않은 날짜는 `—`로 표시한다.
- 내부 상태값은 기존 Context와 호환되도록 `판매 중`, `판매중지`를 유지한다. 화면에서는 `판매 중`, `판매 중지`로 표시한다.

## 목록 내보내기와 복사 등록

- 목록의 **CSV 내보내기**는 현재 검색·판매 상태·단가 범위에 맞는 전체 상품을 현재 정렬순으로 내려받는다. 10개씩 나뉜 현재 페이지에 제한되지 않는다. 조회 결과가 없거나 단가 범위가 잘못되면 버튼이 비활성화된다.
- CSV에는 상품 번호·상품명·기본 단가·판매 상태·한국 기준 등록/수정 시각이 포함된다. Excel의 한글 인식을 위한 UTF-8 BOM을 사용하며 쉼표·따옴표·줄바꿈과 계산식처럼 보이는 이름도 문자로 처리한다. 다운로드는 상품 데이터를 변경하지 않으며 복원·가져오기 기능은 제공하지 않는다.
- 상세의 **상품 복사**는 이름·단가·판매 상태를 채운 **상품 복사 등록** 화면을 연다. 같은 이름으로는 저장할 수 없으므로 새 이름을 입력한다. ID·등록일은 새로 생성하고 수정일은 비워 둔다. 복사 모드는 화면 문구용으로만 사용하며 상품에 저장하지 않는다.
- 복사는 저장할 때만 상품을 추가한다. 취소하면 원본 상세로 돌아가며 원본과 목록은 유지한다. 저장 후에는 목록으로 돌아가 검색·상태·단가 필터를 해제한다.

## 저장과 다른 화면에 미치는 영향

상품 상태는 `ERPProvider`에서 `useProductData()`로 한 번 생성한다. 3번과 같은 방식으로 화면은 `useERP()`의 `products`, `addProduct`, `updateProduct`를 사용해 공통 목록을 공유한다. 상품명·기본 단가는 공통 상품을 참조하는 다른 화면에도 표시될 수 있다. 기존 견적의 `unitPrice`를 일괄 변경하는 기능은 없다.

전달 흐름은 `ProductForm 입력 → ProductPage 편집 충돌 검사 → useProductData 공통 검증 → Context 갱신 → 결과에 따른 화면 안내`이다. 입력값은 `productName`, `productPrice`, `productStatus` 세 필드만 선택한다. 이름 공백 정리·금액 숫자 변환·중복·판매 상태 검증은 상품 Hook에서 수행하므로 다른 화면의 직접 호출에도 적용된다. ID·등록일은 Hook이 신규 등록 때 생성하고, 기존 수정은 요청한 필드·수정일만 반영한다. 검색·페이지·편집 모드 등 화면 전용 값은 보내지 않는다.

**상품 변경은 같은 브라우저·같은 사이트 주소의 localStorage `erp_products`에 저장하며 새로고침 후 복구한다.** 판매 상태뿐 아니라 상품 번호·이름·단가·등록일·수정일과 등록 상품 목록을 함께 유지한다. 저장값이 없을 때만 mockData 초기 목록을 사용하며, 저장된 빈 배열도 그대로 복구한다. 상품 변경을 저장한 시점부터 적용하며, 이전 코드에서 새로고침으로 이미 사라진 메모리 데이터는 복원하지 않는다.

등록·수정·상태 변경은 저장소에 쓰기가 성공한 뒤에만 공통 화면 상태와 성공 결과를 갱신한다. 저장 실패 시 오류를 알리고 이전 상품 정보를 유지하므로 입력을 고치거나 저장소 문제 해결 후 다시 시도할 수 있다. 최초 저장값을 읽거나 검증하지 못하면 초기 목록을 임시 표시하되 경고하고, 원본을 보호하기 위해 변경 저장을 차단한다. 기존 전체 초기화의 명시적 상품 초기화는 초기 목록을 저장하는 동작이며 다른 저장소를 상품 Hook에서 지우지는 않는다.

서버 저장·다른 탭의 실시간 동기화·다른 PC 공유는 제공하지 않는다. 수정 충돌 보호도 현재 Context 기준이며 여러 탭의 동시 저장을 병합하지 않는다. 브라우저 데이터 삭제까지 방지하는 영구 보관 기능은 아니다.

## 팀원 전달용 데이터 규칙

아래는 현재 10번 코드가 사용하는 규칙이다. 별도의 서버 API 명세나 DB 제약을 구현한 것은 아니다.

| 필드 | 자료형 | 필수·입력 주체 | 현재 처리 |
|---|---|---|---|
| `id` | number | 신규 등록 시 자동 생성 | 현재 목록의 최대 숫자 ID + 1. 수정 시 유지. 상품 객체의 키는 `productId`가 아닌 `id` |
| `productName` | string | 사용자 필수 입력 | 원래 입력의 `length`가 최대 100이며 공백만 있는 값은 차단. 앞뒤 공백 제거 후 저장 |
| `productPrice` | number | 사용자 필수 입력 | 0 이상, `Number.isSafeInteger`를 만족하는 정수. 최대 9,007,199,254,740,991원. 쉼표·원 단위를 붙이지 않고 저장 |
| `productStatus` | string | 폼에서 선택 | 신규 기본값 `판매 중`. 허용 저장값은 `판매 중`, `판매중지` 두 가지 |
| `productCreatedAt` | string | 신규 등록 시 자동 생성 | `new Date().toISOString()` 형식. 기존 mockData의 `YYYY-MM-DD` 형식도 표시·정렬 지원. 수정 시 유지 |
| `productUpdatedAt` | string | 실제 변경 시 자동 생성 | 신규 등록은 빈 문자열. 기존 정보·상태 변경 시 ISO 시각 기록. 변경 없는 저장은 유지 |

이름 중복 비교는 앞뒤 공백 제거 → 유니코드 기본 정규화(NFC) → 한국 로케일 소문자 변환 순서로 수행한다. 수정 시 같은 `id`의 상품은 중복 검사에서 제외한다. 내부 공백을 합치거나 이름 자체를 소문자로 저장하지 않는다. 글자 수는 JavaScript 문자열 `length` 기준이므로 일부 이모지는 한 글자처럼 보여도 둘 이상으로 계산될 수 있다.

폼 내부의 단가는 입력 문자열이고 Hook의 검증 단계에서 숫자로 변환된다. Hook은 숫자 또는 숫자로 변환 가능한 문자열을 받으며 빈 문자열·공백만 있는 문자열·null·불리언은 허용하지 않는다. 복사 등록은 이름·단가·상태만 가져오며 새 ID·등록일을 생성한다. 기존 상품 수정은 위 필드 외 추가 정보가 있어도 유지한다. 상품코드·유형·설명은 현재 입력·전달 대상에 포함하지 않는다.

## 팀원 전달용 Context 사용 방식

상태 관리 Hook인 `context/useProductData.js`는 기본 초기 상품을 mockData에서 읽는다. `ERPContext.js`는 `const productData = useProductData()`로 생성하고 `...productData`로 제공한다. 화면은 `const { products, addProduct, updateProduct } = useERP()`로 받아 사용한다. 3번과 같은 흐름이며 별도의 연결 Hook은 두지 않는다. 브라우저에서 mockData 소스 파일에 다시 쓰는 방식은 아니다.

| 연결 단계 | 3번 프로젝트 | 10번 상품 |
|---|---|---|
| 상태·공통 처리 | `useProjectData` | `useProductData` |
| Provider 생성·제공 | `projectData` / `...projectData` | `productData` / `...productData` |
| 화면에서 사용 | `useERP()`의 `projects`, `addProject`, `updateProject` | `useERP()`의 `products`, `addProduct`, `updateProduct` |
| 전체 초기화 | `projectData.resetProjects()` | `productData.resetProducts()` |

상품의 브라우저 저장·복구는 상품 Hook에서 처리하며, 3번의 변경 이력·삭제 기능은 복제하지 않는다. 상품 필드와 Context 연결 방식은 유지한다.

| 방향·동작 | 연결 지점 | 전달 내용·유지 사항 |
|---|---|---|
| Context → 화면 | `useERP().products` | 전체 상품 배열. 조회 조건은 화면에서 적용하고, 상세는 선택 ID로 최신 상품을 찾음 |
| 10번 → Hook → Context: 신규·복사 등록 | `addProduct(values)` | 검증한 입력 세 필드에 새 ID·등록일·빈 수정일을 붙여 추가 |
| 10번 → Hook → Context: 기존 수정 | `updateProduct({ id, ...values })` | 전달한 이름·단가·상태와 수정일만 갱신. ID·등록일·추가 필드·다른 상품 유지 |
| 10번 → Hook → Context: 판매 상태 변경 | `updateProduct({ id, productStatus })` | 확인 승인 후 해당 상품의 상태·수정일만 갱신 |
| 전체 초기화 → 상품 Hook | `productData.resetProducts()` | 상품을 초기 목록의 복사본으로 되돌림. 상품 상태를 화면에서 따로 만들지 않음 |
| Context로 보내지 않는 정보 | 10번의 React 상태·참조 | 검색어·상태 필터·정렬·페이지·선택 ID·편집 모드·입력 중 값·오류·초점 복귀 위치 |

화면에 제공하는 연결 계약은 상품 배열과 등록·수정 함수다. Context는 상품 Hook 결과를 펼쳐 제공하며 기존 소비자의 `products`·`setProducts` 계약도 호환용으로 유지한다. 10번 화면은 `setProducts`를 직접 호출하지 않고 작업별 함수를 사용한다. `useERP()`는 여러 화면에서 호출해도 같은 상태를 공유하지만 상태 생성용 `useProductData()`는 Provider에서만 호출한다. 편집 시작값을 비교하는 충돌 검사는 화면에 남아 있다. 저장 성공 안내는 브라우저 저장 성공 후 표시하며 서버 저장 완료 응답을 의미하지 않는다. 저장소 오류는 `productStorageError`로 제공해 상품 화면에서 안내한다.

### 등록·수정 함수의 결과

| 결과 | 반환 형식 | 호출 화면의 처리 |
|---|---|---|
| 정상 등록·수정 | `{ ok: true, changed: true, product }` | 반환된 상품은 공통 상태에 반영됨. 성공 안내 후 원래 복귀 경로로 이동 |
| 변경 없음 | `{ ok: true, changed: false, product }` | 상태와 수정일 유지. 변경 없음 안내 후 편집 종료 |
| 입력 오류 | `{ ok: false, field, message }` | 상태·수정일과 입력 내용을 유지. 해당 입력 아래에 안내하고 초점 이동 |
| 상품 없음·화면 편집 충돌·저장 실패 | `{ ok: false, field: null, message }` | 폼 전체 오류 안내. 자동 재등록·덮어쓰기하지 않음 |

`field`는 `productName`, `productPrice`, `productStatus` 중 하나 또는 null이다. 폼은 이를 이름·단가·상태 입력에 연결한다. 부분 수정도 기존 값과 합친 최종 상품을 검증하지만 실제 반영은 요청한 필드로 제한한다. 같은 Hook에서 렌더 전에 연속 호출하더라도 최신 목록으로 검증해 중복 등록·이름 변경을 차단한다. 다른 탭·PC에 대한 동시성 보장을 의미하지는 않는다.

호환용 `setProducts`는 저수준 상태 교체 함수라 입력 검증을 수행하지 않는다. 다른 화면의 상품 등록·수정도 `addProduct`·`updateProduct`를 사용해야 공통 검증을 거친다.

같은 상품의 이름·단가·상태·등록일·수정일이 편집 시작값과 달라지거나 상품이 없어지면 저장을 차단한다. 이 검사는 화면이 받은 최신 Context 기준이며 서버의 버전 검사·트랜잭션을 대체하지 않는다. 현재 ID 생성도 한 앱 인스턴스의 목록을 기준으로 하므로 여러 사용자 동시 등록의 ID 발급 방식은 추후 저장 연동 때 정해야 한다.

공통 상품을 참조하는 화면에는 변경된 상품 정보가 반영될 수 있다. 기존 견적 객체의 `unitPrice`나 다른 파트 데이터에 직접 쓰는 코드는 10번에 없다. 다른 화면에서도 판매 중지 상품 선택을 차단하는지는 이번 작업에서 확인하거나 구현하지 않았다.
