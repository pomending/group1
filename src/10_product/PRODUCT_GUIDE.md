# 상품관리 사용 안내

기준일: 2026-11-04. 접속 주소는 `/product`이다.

## 목록과 상세

- 상품명 검색·판매 상태·단가 범위 필터와 상품명/단가/등록일/최근 수정순 정렬을 사용할 수 있다. 조건을 바꾸면 첫 페이지로 돌아간다.
- 검색도 중복 검사와 같은 기준으로 앞뒤 공백·영문 대소문자·한글 유니코드 표기를 정리해 비교한다. 상품 이름 자체는 바꾸지 않는다.
- 등록일은 실제 시각순으로 정렬한다. 날짜만 있는 자료는 한국 자정 기준으로 비교하며 날짜가 없거나 잘못된 자료는 최신순·오래된순 모두 마지막에 표시한다.
- 검색 결과가 없으면 **조건 초기화**로 검색·판매 상태·단가 범위를 해제할 수 있다. 정렬은 유지하고 검색칸으로 초점을 옮긴다. 상단 **초기화**는 정렬도 등록일 최신순으로 되돌린다.
- **추가 검색 조건**을 펼쳐 최소·최대 단가를 입력하면 바로 조회한다. 0원과 양 끝 금액을 포함하며 빈 경계는 제한 없음이다. 조건을 접어도 적용하고 제목에 적용 중임을 표시한다. 음수·소수·안전한 정수 범위 초과·최소가 최대보다 큰 경우에는 오류를 안내하고 조회·CSV 내보내기를 제한한다. 올바른 값으로 고치거나 초기화하면 복구된다.
- **최근 수정순**은 저장된 수정일의 실제 시각 내림차순이다. 수정일이 없거나 잘못된 상품은 뒤에 배치한다. 같은 시각이거나 둘 다 유효한 수정일이 없으면 기존과 같이 ID순으로 정한다. 등록일을 수정일로 대체하지 않는다.
- 목록은 10개씩 표시한다. 상단 현황은 전체 상품 기준이고 조회 건수는 검색·필터 결과 기준이다.
- 현황 카드를 누르면 판매 상태 필터가 함께 바뀌고 첫 페이지로 이동한다. 검색어·단가 범위·정렬은 유지하며 선택된 카드를 강조한다. **전체 상품** 카드는 판매 상태만 해제한다. 카드는 기본 버튼이므로 Enter·Space로도 선택할 수 있다.
- 조회 건수는 검색어·판매 상태·적용한 단가 범위와 함께 보조기기에 알린다. 실제 스크린리더의 낭독 동작은 별도 확인이 필요하다.
- 상품명을 누르면 상세 화면이 열린다. **상품 수정**으로 편집하거나 **목록으로** 돌아간다.
- 상세 상단에는 상품명·단가·판매 상태를 강조하고, 하단 **관리 정보**에는 상품 번호·등록일·수정일을 표시한다. 긴 이름은 줄바꿈하며 좁은 화면에서는 한 열로 배치한다.
- 목록으로 돌아오면 검색·정렬·페이지를 유지한다. 원래 상품 버튼이 없으면 목록 제목으로 초점을 이동한다.

## 등록·수정

화면 제목은 **상품 등록 / 상품 수정 / 상품 복사 등록**으로 구분한다. 저장 버튼은 신규·복사 등록에서 **등록 저장**, 기존 상품 수정에서 **수정 저장**으로 표시한다. 복사 준비 안내는 아직 상품이 추가되지 않은 상태이며 **등록 저장**을 눌러야 목록에 반영된다.

| 항목 | 규칙 |
|---|---|
| 상품명 | 필수, 최대 100자. 앞뒤 공백을 제거해 저장하며 영문 대소문자·동일 유니코드 표기만 다른 이름도 중복으로 처리 |
| 기본 단가 | 필수, 0 이상의 안전한 정수 |
| 판매 상태 | 판매 중 또는 판매 중지 |
| 상품 번호·등록일 | 새 상품 저장 시 자동 생성 |
| 최종 수정일 | 정보나 판매 상태가 실제로 변경될 때 갱신. 변경 없이 저장하면 기존 날짜 유지 |

- 오류는 해당 입력칸 아래에 표시하고 첫 오류 칸으로 초점을 옮긴다. 해당 값을 입력하면 안내가 해제되며 저장할 때 다시 검증한다.
- 상품명·기본 단가에 필수를 표시한다. 이름 입력 아래에는 현재 글자 수와 최대 100자 안내, 금액 아래에는 원 단위 정수 안내를 표시한다. 안내와 오류는 입력칸의 접근성 설명에도 연결한다.
- 유효한 금액 아래에는 쉼표를 넣은 미리보기(예: `12,000원`)를 표시한다. 빈 값·음수·소수·안전한 정수 범위를 넘는 값은 미리보기를 숨긴다. 입력 문자열과 저장할 숫자 형식은 바꾸지 않는다.
- 작성 중 **취소**를 누르면 변경 내용 폐기를 확인한다. 변경이 없거나 원래 입력값으로 돌아왔으면 바로 닫힌다. 새로고침·페이지 이동 전에는 필요한 내용을 저장해야 한다.
- 취소 확인 문구는 신규 등록·기존 상품 수정·복사 등록에 맞춰 구분한다. 확인을 거절하면 입력을 그대로 유지한다.
- 수정 중 같은 상품의 정보가 Context에서 변경되거나 삭제되면 저장을 차단한다. 입력은 유지되므로 필요한 내용을 확인한 뒤 취소하고 최신 상품을 다시 연다. 다른 상품의 변경은 유지하면서 저장할 수 있다.
- 수정 후에는 기존 목록 조건을 유지한다. 새로 등록한 경우에는 검색·상태·단가 필터를 해제하고 첫 페이지로 이동한다.

## 판매 상태와 날짜

- 목록의 **판매 중지/판매 재개** 버튼은 확인을 승인한 경우에만 해당 상품의 상태·수정일을 변경한다. 필터에서 상품이 사라질 수 있다.
- 목록 날짜와 상세 시각은 한국 시간(KST) 기준이다. 날짜만 저장된 자료에는 임의의 시간을 붙이지 않고, 비어 있거나 유효하지 않은 날짜는 `—`로 표시한다.
- 내부 상태값은 기존 Context와 호환되도록 `판매 중`, `판매중지`를 유지한다. 화면에서는 `판매 중`, `판매 중지`로 표시한다.

## 목록 내보내기와 복사 등록

- 목록의 **CSV 내보내기**는 현재 검색·판매 상태·단가 범위에 맞는 전체 상품을 현재 정렬순으로 내려받는다. 10개씩 나뉜 현재 페이지에 제한되지 않는다. 조회 결과가 없거나 단가 범위가 잘못되면 버튼이 비활성화된다.
- CSV에는 상품 번호·상품명·기본 단가·판매 상태·한국 기준 등록/수정 시각이 포함된다. Excel의 한글 인식을 위한 UTF-8 BOM을 사용하며 쉼표·따옴표·줄바꿈과 계산식처럼 보이는 이름도 문자로 처리한다. 다운로드는 상품 데이터를 변경하지 않으며 복원·가져오기 기능은 제공하지 않는다.
- 상세의 **상품 복사**는 이름·단가·판매 상태를 채운 **상품 복사 등록** 화면을 연다. 같은 이름으로는 저장할 수 없으므로 새 이름을 입력한다. ID·등록일은 새로 생성하고 수정일은 비워 둔다. 복사 모드는 화면 문구용으로만 사용하며 상품에 저장하지 않는다.
- 복사는 저장할 때만 상품을 추가한다. 취소하면 원본 상세로 돌아가며 원본과 목록은 유지한다. 저장 후에는 목록으로 돌아가 검색·상태·단가 필터를 해제한다.

## 저장과 다른 화면에 미치는 영향

현재 `ERPContext.products`를 읽고 `setProducts`로 같은 앱의 공통 상품 상태를 변경한다. 상품명·기본 단가는 공통 상품을 참조하는 다른 화면에도 표시될 수 있다. 기존 견적의 `unitPrice`를 일괄 변경하는 기능은 없다.

10번 내부의 전달 흐름은 `ProductForm 검증 → ProductPage.saveProduct → getProductInput → setProducts`이다. 입력값은 `productName`, `productPrice`, `productStatus` 세 필드만 선택한다. ID·등록일은 신규 등록 때 생성하고, 기존 수정은 `updateProduct`로 변경 필드·수정일만 반영한다. 목록의 판매 상태 변경도 같은 갱신 함수를 사용한다. 검색·페이지·편집 모드 등 화면 전용 값은 보내지 않는다.

**현재 Context에는 상품 변경 내용을 영구 저장하는 처리가 없어 새로고침하면 초기 데이터로 돌아간다.** 수정 충돌 보호도 현재 Context에 반영된 변경에 대한 검사이며 다른 탭·PC의 동기화를 제공하지 않는다. 저장 유지 기능은 Context 수정 범위를 별도로 확인한 후 진행한다.

## 팀원 전달용 데이터 규칙

아래는 현재 10번 코드가 사용하는 규칙이다. 별도의 서버 API 명세나 DB 제약을 구현한 것은 아니다.

| 필드 | 자료형 | 필수·입력 주체 | 현재 처리 |
|---|---|---|---|
| `id` | number | 신규 등록 시 자동 생성 | 현재 목록의 최대 숫자 ID + 1. 수정 시 유지. 상품 객체의 키는 `productId`가 아닌 `id` |
| `productName` | string | 사용자 필수 입력 | 원래 입력의 `length`가 최대 100이며 공백만 있는 값은 차단. 앞뒤 공백 제거 후 저장 |
| `productPrice` | number | 사용자 필수 입력 | 0 이상, `Number.isSafeInteger`를 만족하는 정수. 최대 9,007,199,254,740,991원. 쉼표·원 단위를 붙이지 않고 저장 |
| `productStatus` | string | 폼에서 선택 | 신규 기본값 `판매 중`. 허용 저장값은 `판매 중`, `판매중지` 두 가지 |
| `productCreatedAt` | string | 신규 등록 시 자동 생성 | `new Date().toISOString()` 형식. 기존 mockData의 `YYYY-MM-DD` 형식도 표시·정렬 지원. 수정 시 유지 |
| `productUpdatedAt` | string | 실제 변경 시 자동 생성 | 신규 등록은 빈 문자열. 기존 정보·상태 변경 시 ISO 시각 기록. 변경 없는 저장은 유지 |

이름 중복 비교는 앞뒤 공백 제거 → 유니코드 기본 정규화(NFC) → 한국 로케일 소문자 변환 순서로 수행한다. 수정 시 같은 `id`의 상품은 중복 검사에서 제외한다. 내부 공백을 합치거나 이름 자체를 소문자로 저장하지 않는다. 글자 수는 JavaScript 문자열 `length` 기준이므로 일부 이모지는 한 글자처럼 보여도 둘 이상으로 계산될 수 있다.

폼 내부의 단가는 입력 문자열이고 저장 직전에 숫자로 변환된다. 복사 등록은 이름·단가·상태만 가져오며 새 ID·등록일을 생성한다. 기존 상품 수정은 위 필드 외 추가 정보가 있어도 유지한다. 상품코드·유형·설명은 현재 입력·전달 대상에 포함하지 않는다.

## 팀원 전달용 Context 사용 방식

10번은 `mockData.js`를 직접 가져오지 않고 `useERP()`를 사용한다. 현재 Context가 초기 상품을 mockData에서 읽고, 실행 중 변경은 공통 메모리 상태에 반영한다. 브라우저에서 mockData 소스 파일에 다시 쓰는 방식은 아니다.

| 방향·동작 | 연결 지점 | 전달 내용·유지 사항 |
|---|---|---|
| Context → 10번 | `useERP().products` | 전체 상품 배열. 조회 조건은 화면에서 적용하고, 상세는 선택 ID로 최신 상품을 찾음 |
| 10번 → Context: 신규·복사 등록 | `setProducts(current => ...)` | 검증한 입력 세 필드에 새 ID·등록일·빈 수정일을 붙여 추가 |
| 10번 → Context: 기존 수정 | `setProducts` + `updateProduct` | 같은 ID의 이름·단가·상태와 수정일만 갱신. ID·등록일·추가 필드·다른 상품 유지 |
| 10번 → Context: 판매 상태 변경 | `setProducts` + `updateProduct` | 확인 승인 후 해당 상품의 상태·수정일만 갱신 |
| Context로 보내지 않는 정보 | 10번의 React 상태·참조 | 검색어·상태 필터·정렬·페이지·선택 ID·편집 모드·입력 중 값·오류·초점 복귀 위치 |

현재 연결 계약은 `products` 배열과 React 상태 갱신 함수 `setProducts` 두 가지다. 10번에서 함수형 갱신을 사용하므로 Context를 변경할 팀원은 이 호출 방식도 지원해야 한다. 저장 성공 안내는 현재 Context에 반영했다는 의미이며 서버 저장 완료 응답을 의미하지 않는다.

같은 상품의 이름·단가·상태·등록일·수정일이 편집 시작값과 달라지거나 상품이 없어지면 저장을 차단한다. 이 검사는 화면이 받은 최신 Context 기준이며 서버의 버전 검사·트랜잭션을 대체하지 않는다. 현재 ID 생성도 한 앱 인스턴스의 목록을 기준으로 하므로 여러 사용자 동시 등록의 ID 발급 방식은 추후 저장 연동 때 정해야 한다.

공통 상품을 참조하는 화면에는 변경된 상품 정보가 반영될 수 있다. 기존 견적 객체의 `unitPrice`나 다른 파트 데이터에 직접 쓰는 코드는 10번에 없다. 다른 화면에서도 판매 중지 상품 선택을 차단하는지는 이번 작업에서 확인하거나 구현하지 않았다.

## 완료·검증·보류 사항

구현 여부와 검증 수준을 구분한다. 아래 브라우저 결과는 사용자가 전달한 재검사 보고서 기준이며, 이 문서 작성 중 새로 브라우저 검사를 수행한 것은 아니다.

| 구분 | 내용 | 근거·제한 |
|---|---|---|
| 구현 완료 | 등록·수정·복사, 판매 상태 변경, 상세, 검색·상태·단가 범위 필터·정렬·페이지, CSV 내보내기 | 자동 테스트 58개 통과. 실제 서버·영구 저장을 검증한 결과는 아님 |
| 추가 기능 브라우저 미실행 | 단가 범위 입력·접기·오류 안내·CSV 반영, 최근 수정순 | 자동 검사로 경계값·잘못된 범위·초기화·상태 조합·페이지 복귀·금액 CSV·수정일 정렬 확인. 기존 브라우저 보고에는 없는 추가 기능 |
| 브라우저 통과 | 1440·768·375px 목록·등록·수정·상세 배치, 표 내부 가로 스크롤 | 보고된 검사 화면에서 페이지 전체 가로 넘침·겹침 미발견 |
| 브라우저 통과 | 카드 Enter·Space 선택, 검색·정렬 유지, 상세·편집 취소 후 초점 복귀 | 전체 요소의 Tab 순회를 모두 검사한 것은 아님 |
| 브라우저 통과 | 긴 한글·영문·무공백 이름 입력, 글자 수, 금액 미리보기, 조회 건수 | 입력 검사는 저장하지 않음. 긴 이름의 목록·상세 표시는 미실행 |
| 브라우저 부분 확인 | 접근성 조회 안내, 콘솔 기록 | 접근성 속성 확인. 실제 낭독 미실행. 최종 콘솔 조회는 빈 목록이나 전체 구간 무오류 보장은 아님 |
| 브라우저 미실행 | 10건 초과 페이지 이동·첫 페이지 복귀 | 기존 상품이 10건이며 검사 목적의 상품 추가를 하지 않음 |
| 브라우저 미실행 | 변경 후 폐기 확인창의 취소·승인 과정 | 도구 시간 초과 후 작성 내용 폐기만 관찰. 취소에 따른 입력 유지 과정은 확정하지 못함 |
| 브라우저 미실행 | CSV 다운로드, 해당 검사에서의 상품 저장·판매 상태 변경 | 기존 데이터 보호를 위해 실행하지 않음. 자동 테스트 결과와 구분 |
| 보류 | 새로고침 후 저장 유지, 서버 API, 다른 탭·PC 동기화, 동시 등록 ID 발급 | Context·서버 등 10번 밖 변경이 필요하면 대상·코드·영향을 먼저 공유하고 명시적 승인 후 진행 |

현재 보고에서 확정된 화면 결함은 없다. 미실행 항목이나 브라우저 도구 시간 초과를 앱 오류로 단정하지 않는다. 검증용 기존 상품 변경이나 새 상품 저장은 보고된 브라우저 검사에서 수행하지 않았다.

## 파일별 수정 위치

| 파일 | 담당 |
|---|---|
| `ProductPage.js` | Context 연결, 목록·화면 전환, 저장·충돌 검사, 초점 복원 |
| `ProductForm.js` | 입력·검증·오류 안내·취소 확인 |
| `ProductDetails.js` | 주요 상품·관리 정보 표시, 목록·수정·복사 등록 이동 |
| `productData.js` | 전달 필드 선택·상품 갱신·상태 규칙·이름 비교·날짜 표시/정렬·CSV 변환 |
| `productStyles.css` | 상품관리 전용 스타일과 반응형 배치 |
| `ProductPage.test.js` | 테스트용 Context로 등록·수정·필터·상세·충돌·초점·날짜·CSV·금액 미리보기·조회 안내 검사 |

검사 명령: `npm test -- --watchAll=false --runInBand src/10_product`

자동 검사는 테스트용 Context를 사용하며 실제 브라우저 저장소나 기존 상품을 수정하지 않는다. 실제 화면의 확인 범위와 남은 항목은 위 검증 표를 따른다.
