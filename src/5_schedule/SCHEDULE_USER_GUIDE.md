# 일정관리 사용 안내

현재 화면 기준: 2026-10-29. 이 문서는 개발 도구에서 읽는 안내이며 사이트에 자동 표시되지 않는다.

## 1. 일정 등록

1. 달력에서 날짜를 선택하고 **일정 등록**을 누른다.
2. **업무용** 또는 **개인 일정용**을 선택한다.
3. 일정 이름·날짜·시간을 입력한다.
4. 업무용이면 업무 분류와 담당자를 입력한다. 회의는 참석자를 선택할 수 있고, 프로젝트 분류는 프로젝트명을 입력해야 한다.
5. 상세 내용을 입력하고 필요하면 그 아래의 **추가 설정 · 공유 구분·반복·알림**을 펼친다.
6. **일정 저장**을 누르고 상단의 저장 상태를 확인한다.

업무용과 개인 일정용을 바꾸면 프로젝트·담당자·참석자 등 업무 입력값이 초기화된다. 회의나 프로젝트 분류를 벗어날 때에도 해당 전용 입력값이 비워진다.

## 2. 일정 종류와 공유 구분

| 구분 | 선택값 | 의미 |
|---|---|---|
| 일정 종류 | 업무용 / 개인 일정용 | 필요한 입력 항목과 업무 상태 표시를 결정 |
| 공유 구분 | 회사 공유 / 개인 표시 | 달력 필터와 배지에 사용하는 표시 구분 |

두 설정은 별개다. 개인 일정용을 선택해도 공유 구분이 자동 변경되지는 않는다.

현재 **개인 표시는 본인만 볼 수 있도록 권한을 제한하는 기능이 아니다.** 회사 공유도 서버를 통해 다른 직원에게 일정을 전송하는 기능을 뜻하지 않는다.

## 3. 날짜·시간과 여러 날 일정

- 같은 날 일정은 종료 시간을 시작 시간보다 늦게 입력한다.
- 여러 날 일정은 반복을 **반복 없음**으로 두고 추가 설정의 **종료 날짜**를 지정한다.
- 예: 11월 4일 18시 시작, 종료 날짜 11월 5일, 종료 시간 9시로 등록할 수 있다.
- 이 일정은 두 날짜에 표시된다. 첫날 카드에는 `18:00~24:00`, 마지막 날에는 `00:00~09:00`으로 표시된다.
- **종일 일정**을 선택하면 시간 입력이 숨겨진다. 여러 날 종일 일정도 등록할 수 있다.
- 여러 날 일정은 연속된 한 건이다. 중간 날짜에서 수정해도 해당 날짜만 분리하는 반복 회차 수정과는 다르다.

## 4. 일정 확인·수정

- 달력의 일정 제목을 누르면 해당 날짜의 상세 패널이 표시된다. 상세 패널의 **수정**을 눌러 편집한다.
- 긴 제목은 두 줄로 생략될 수 있다. 월간 카드의 **전체 이름**을 눌러 펼치거나 접는다.
- 별표는 즐겨찾기만 변경한다. 전체 이름 펼치기와 일정 선택은 별도 동작이다.
- **전체 일정** 목록의 제목이나 즐겨찾기 제목에서는 수정 창으로 바로 들어갈 수 있다.
- 편집 후 **수정 저장**을 누른다. 이름·날짜 등이 검색 조건과 달라져도 확인할 수 있도록 저장 후 필터가 초기화된다.

## 5. 월간 반복과 휴일 규칙

### 매월 둘째 수요일

1. 반복 설정에서 **매월**을 선택한다.
2. 매월 기준을 **몇째 주 요일**, 주차를 **둘째 주**, 요일을 **수요일**로 설정한다.
3. 등록 날짜는 반복의 시작 기준이다. 그 날짜보다 앞선 회차는 생성되지 않는다.

예를 들어 시작일이 2026-11-01이면 2026-11-11, 2026-12-09가 표시된다.

### 주말·공휴일 처리

| 선택값 | 동작 |
|---|---|
| 기준일에 진행 | 주말·공휴일이어도 원래 발생일에 표시 |
| 건너뛰기 | 해당 회차를 표시하지 않음 |
| 다음 근무일로 이동 | 뒤의 평일이며 공휴일이 아닌 날짜로 이동 |

매월 1일 반복에서 다음 근무일 이동을 선택하면 2026-11-01은 11-02로, 공휴일 정보가 정상 조회된 2027-01-01은 01-04로 이동한다.

표시 연도와 앞뒤 연도 중 하나라도 공휴일 조회에 실패하면 경고가 표시된다. 성공한 연도의 정보는 유지되지만, 실패한 연도의 공휴일 판단은 정확하지 않을 수 있다. 주말 판단과 공휴일 조회는 별개이며, 이동 날짜는 최대 14일 탐색한다.

### 반복 종료

추가 설정에서 반복 종류를 고르면 **반복 종료**를 선택할 수 있다.

- **종료일 없음**: 기존처럼 계속 반복한다.
- **날짜 지정**: **반복 종료 날짜**까지의 원래 규칙 회차를 포함한다. 시작일 이상을 입력한다. 휴일 이동 결과는 종료일을 넘을 수 있다.
- **횟수 지정**: **반복 횟수**를 1~1000 사이로 입력한다. 휴일로 건너뛰거나 삭제한 회차도 규칙 횟수에 포함한다.

예: 11월 4일 시작 매주 반복을 3회로 설정하면 11월 4일·11일·18일이 해당한다. 중간 회차를 삭제해도 25일을 추가로 만들지는 않는다. 한 회차 수정에서는 원본 반복 종료 조건을 변경하지 않는다.

## 6. 한 회차와 전체 반복 수정·삭제

| 원하는 범위 | 진입 방법 | 결과 |
|---|---|---|
| 특정 회차만 수정·삭제 | 달력에서 해당 날짜 선택 → 상세 패널 | 다른 회차는 유지. 수정한 회차는 별도 일반 일정으로 저장 |
| 원본 반복 전체 수정·삭제 | 전체 일정 목록에서 원본 반복 선택 | 원본 반복 규칙에 적용 |

수정 창에 **선택한 날짜의 일정만 수정합니다**라는 안내가 있으면 한 회차 편집이다. 삭제 확인창에서도 해당 날짜인지 **전체 반복 일정**인지 확인한다.

이미 한 회차를 수정해 별도 일반 일정이 된 항목은 독립된 저장 항목이다. 원본 반복 전체를 삭제해도 함께 삭제된다고 가정하지 말고 해당 항목을 따로 확인한다.

## 7. 검색·목록·다가오는 일정

- 검색은 일정명·프로젝트·담당자·참석자를 기준으로 현재 보기 기간의 결과를 보여준다.
- **공유 구분 필터**는 일정 종류 필터가 아니다. 회사 공유·개인 표시 값을 기준으로 조회한다.
- 즐겨찾기와 다가오는 목록은 달력 검색과 별도 기준이다. 검색으로 달력이 비어 있어도 이 목록은 남을 수 있다.
- 다가오는 목록은 오늘 포함 7일 이내의 미완료 일정 중 가까운 5건이다. 시작 전뿐 아니라 아직 종료되지 않은 일정도 포함하며, 여러 날 일정은 한 번만 표시한다.
- 프로젝트 시작·마감일로 표시되는 읽기 전용 항목은 이 화면에서 수정·삭제하지 않는다.

## 8. 팝업 닫기와 키보드

- **Esc**로 닫고, **Tab / Shift+Tab**으로 팝업 안에서 이동한다.
- 닫은 뒤에는 팝업을 열었던 위치로 초점이 돌아간다. 원래 요소가 없어졌으면 대체 위치로 이동할 수 있다.
- 입력을 바꾼 뒤 취소·닫기·배경 클릭·Esc로 닫으면 변경 내용을 버릴지 확인한다.
- 확인창에서 취소하면 입력을 유지한다. 확인하면 저장하지 않고 닫는다.
- 변경을 원래 값으로 되돌렸으면 추가 확인 없이 닫힌다. 전체 목록창에는 작성 중 확인이 없다.
- 이 보호는 팝업 닫기용이다. **브라우저 새로고침·탭 닫기 전에 필요한 입력을 저장한다.**

## 9. 저장 상태와 오류 대응

| 화면 표시 | 의미와 다음 행동 |
|---|---|
| 저장 중… | 저장 처리 또는 다른 탭의 저장 잠금을 기다리는 중 |
| 브라우저에 저장 완료 | 일정 목록이 현재 브라우저 저장소에 기록됨 |
| 저장 실패 | 상세 경고를 확인한다. 새로고침 전에 저장되지 않은 변경 내용을 별도로 보관한다. |
| 저장 중지 | 원본 읽기 실패 또는 탭 사이 충돌. 상세 안내를 확인한다. |

수정창의 미제출 입력이나 팀원 저장까지 완료됐다는 뜻은 아니다. 팀원 저장 문제는 별도 경고로 표시된다.

프로젝트에 연결된 일정 요약은 일정 저장에 성공한 뒤에만 갱신된다. 저장 실패·충돌 중인 변경은 프로젝트로 전달하지 않는다. 같은 사이트의 여러 탭에서 서로 다른 팀원을 추가하면 이름별로 합치며, 다른 탭에서 제외한 팀원은 오래된 목록 때문에 다시 등록되지 않도록 처리한다.

충돌 또는 읽기 실패 경고의 **현재 변경을 버리고 저장된 일정 불러오기**는 현재 목록 변경을 버리고 저장된 목록으로 돌아가는 동작이므로 내용을 확인한 뒤 사용한다. 저장소 접근 문제나 원본 문제를 해결한 뒤 누르면, 정상적으로 읽은 경우 읽기 오류를 해제하고 자동 저장을 재개한다. 다시 읽지 못하면 저장 중지를 유지하며 원본을 덮어쓰지 않는다.

일정은 같은 사이트 주소의 브라우저 저장소에 저장된다. 다른 PC·브라우저·사이트 주소에는 자동으로 동기화되지 않는다. 알림도 화면이 열린 동안의 안내이며 휴대폰이나 OS 푸시가 아니다.

개발용 필드·기본값·이전 자료 처리 규칙은 [데이터 명세](./SCHEDULE_DATA_SPEC.md)를 참고한다.

## 10. 일정 복사

1. 복사할 일정의 **수정** 창을 연다.
2. **일정 복사**를 누른다. 편집 중 바꾼 값이 있으면 폐기 확인 후 저장돼 있던 원본을 복사한다.
3. 이름에 **(복사)**가 붙은 신규 등록창에서 날짜·시간 등을 변경한다.
4. **일정 저장**을 눌러 새 일정을 만든다. 저장 전에는 원본 일정 수가 늘지 않는다.

원본은 변경되지 않으며 복사본은 새 ID, 예정 상태, 즐겨찾기 해제로 저장된다. 반복 전체를 복사하면 반복 규칙과 종료 조건은 유지하지만 삭제·제외한 회차는 가져오지 않는다. 특정 날짜의 반복 회차 수정창에서 복사하면 해당 날짜의 일반 일정으로 등록한다. 읽기 전용 프로젝트 날짜는 복사 대상이 아니다.

## 11. 전체 목록 정렬

**전체 일정** 또는 날짜별 더보기 목록 상단의 도구 영역에서 정렬·진행 상태·표시 건수를 함께 확인한다. **목록 정렬**은 날짜순·이름순·담당자순을 지원한다. 담당자가 없는 일정은 담당자순에서 뒤에 두고, 같은 이름·담당자는 날짜와 시간으로 정렬한다.

정렬은 해당 목록의 표시 순서만 바꾼다. 일정 내용이나 저장 원본 배열을 수정하지 않으며 목록을 새로 열면 기본 날짜순으로 시작한다.

목록은 한 페이지에 최대 20건을 표시한다. 하단에서 전체 건수와 표시 범위를 확인하고 이전·다음 페이지로 이동한다. 정렬이나 날짜 조건을 바꾸면 첫 페이지로 돌아간다.

## 12. 검색·필터 초기화

검색어·공유 구분·프로젝트 조건 중 하나라도 적용되면 달력 상단에 **검색·필터 초기화**가 나타난다. 누르면 세 조건을 함께 해제하며, 보고 있던 기간·보기 방식·선택 날짜는 유지한다. 검색창의 초기화 아이콘은 검색어만 지운다.

## 13. 반복 요약과 진행 상태

반복 일정을 등록하거나 반복 전체를 수정하면 추가 설정 바깥에 반복 주기·시간·휴일 처리·종료 조건을 요약해 표시한다. 설정을 접어도 요약은 유지된다. 한 회차만 수정할 때는 반복 설정을 바꾸지 않으므로 해당 요약을 표시하지 않는다.

업무 일정의 진행 상태는 **예정·완료** 두 가지다. 달력·목록·선택 날짜 상세는 같은 상태 배지를 사용하고 수정 창과 상세의 상태 선택도 같은 문구와 색상을 사용한다. 개인 일정과 읽기 전용 프로젝트 날짜에는 업무 진행 상태를 표시하지 않는다.

## 14. 선택 날짜와 시간 빠른 설정

달력에서 날짜를 선택한 뒤 **일정 등록**을 누르면 선택한 날짜로 시작한다. 수정 창은 기존 일정의 날짜를 유지한다.

종일이 아닌 일정은 시간 입력 아래의 **30분·1시간·2시간**으로 시작 시간부터의 길이를 정할 수 있다. 기존 종료 날짜·시간을 바꾸며, 일반 일정은 자정을 넘으면 다음 날을 종료 날짜로 설정한다. 당일 종료만 지원하는 반복 일정에서는 다음 날로 넘어가는 버튼이 비활성화된다. 종일 일정에는 빠른 설정을 표시하지 않는다.

저장할 때 일정명과 상세 내용의 앞뒤 공백을 제거한다. 상세 내용 중간의 줄바꿈·들여쓰기는 유지한다. 저장된 기존 일정은 해당 일정을 직접 저장할 때만 적용된다.

## 15. 삭제 되돌리기

삭제 확인 후 나타나는 안내에서 **삭제 되돌리기**를 누르면 최근 삭제 한 건을 복원한다. 기록은 15초 동안만 유지하며 다음 삭제가 확정되면 새 기록으로 바뀐다. 삭제 확인을 취소하면 기존 기록은 그대로 남는다. 안내를 닫거나 페이지를 새로고침하면 되돌리기 기록은 사라진다.

일반·반복 전체 삭제는 원본을 다시 추가하고, 한 회차 삭제는 원본 반복의 삭제 전 제외일 목록을 복구한다. 다른 일정의 변경은 유지한다. 같은 ID가 다시 등록되었거나 원본 반복이 변경·삭제되었다면 덮어쓰지 않고 안내한다. 저장 완료 상태에서만 되돌릴 수 있으며 실행 후에도 상단 저장 상태를 확인한다. 영구 휴지통이나 여러 단계 실행 취소 기능은 아니다.


## 16. 입력칸별 오류 안내

잘못된 입력은 하단 안내와 함께 관련 입력칸 근처에도 표시한다. 입력칸은 오류 문구와 연결되며 값을 바꾸면 다시 검사할 수 있다. 추가 설정 안의 종료 날짜·반복 종료·횟수 오류는 설정을 자동으로 펼쳐 확인하도록 한다. 다른 탭 충돌 같은 저장 오류는 기존 하단 안내를 유지한다.

입력창의 글자 수 제한뿐 아니라 저장 직전에도 일정 이름 80자, 프로젝트명 60자, 상세 내용 3,000자, 담당자·참석자 이름 30자를 검사한다. 프로젝트명은 업무용의 프로젝트 분류, 참석자는 회의 분류에 적용한다. 일정 상태·공유 구분·알림·반복 방식·월간 반복 기준은 허용된 선택값만 저장할 수 있다. 추가 설정의 오류는 해당 구역을 펼치고 관련 입력과 안내문을 연결한다.

저장된 일정 번호가 중복되거나 일정·팀원 저장값의 JSON이 손상되면 읽기와 자동 저장을 중지해 원본을 보호한다. 프로젝트 연동이 실패해도 저장된 일정과 화면은 유지하며 별도 경고를 표시한다. 일정 저장 완료와 프로젝트 연동 완료는 구분해서 확인한다.

## 17. 새 일정 임시 보관

새 일정 등록 내용을 같은 탭에 자동으로 임시 보관한다. 새로고침 후 **이어서 작성**으로 입력한 내용을 복구한다. 임시 내용이 있으면 **일정 등록**을 눌러도 이어서 작성한다. 실제 저장 전에는 일정 목록·프로젝트·팀원 데이터가 바뀌지 않는다.

등록 완료 또는 닫기 확인을 승인하면 임시 내용을 제거한다. **임시 보관 삭제**로도 지울 수 있다. 복구한 내용을 변경하지 않았더라도 닫을 때 폐기 여부를 확인한다. 임시 보관은 현재 탭의 세션 저장소를 사용하므로 탭을 닫은 뒤의 영구 보관을 보장하지 않는다. 기존 일정 수정은 임시 보관하지 않는다. 저장소 접근이 막히거나 임시 자료가 손상되면 안내하며 손상된 내용을 자동으로 덮어쓰지 않는다.

## 18. 목록 진행 상태 필터

전체·날짜별 일정 목록의 **목록 진행 상태**에서 전체·예정 업무·완료 업무를 선택한다. 예정·완료는 업무 일정만 표시하며 개인 일정은 전체에서 확인한다. 선택 시 첫 페이지로 돌아가며 정렬은 유지한다. 필터는 목록 표시만 바꾸고 실제 일정 상태나 달력 조건을 바꾸지 않는다.

상태 필터로 결과가 없으면 **진행 상태 전체 보기**로 돌아갈 수 있다. 원래 목록 자체가 비어 있으면 상태 필터 해제 대신 등록 안내를 표시한다. 날짜별 목록과 담당자별 주간 보기도 검색·필터 결과가 없는 경우를 등록 데이터가 없는 경우와 구분한다.

## 프로젝트 연결 보호 보완

저장 복원 시 알림·반복 간격·반복 횟수·월간 주차·요일은 숫자와 비어 있지 않은 숫자 문자열만 해석한다. 배열·불리언·손상된 객체는 기본값으로 보완하며, 값이 변경되는 경우 기존 JSON을 백업한다. 업무 유형과 일정 색상도 같은 허용 목록을 기준으로 복원한다.

저장된 일정 중 삭제된 프로젝트 ID, 견적·고객이 달라진 프로젝트 ID, 이름만 있고 동명 프로젝트가 여러 개인 연결은 **프로젝트 연결 확인 필요** 목록에 표시한다. 일정의 **연결 확인** 버튼으로 편집창을 열어 사유를 확인할 수 있다. **프로젝트 다시 선택**은 편집 중인 프로젝트 입력과 연결 기준을 비우며, 새 값을 선택하고 저장하기 전까지 원본은 유지한다. 프로젝트 분류를 유지하면 새 프로젝트명이 필요하고, 독립 일정으로 바꾸려면 업무 분류도 변경한다. 연결 기준이 없는 과거 일정의 ID 재사용 여부는 자동으로 확정할 수 없다.

프로젝트 연동 실패 안내에는 대상 프로젝트와 거절 사유를 표시한다. 원인을 해결한 뒤 **프로젝트 연동 다시 시도**로 저장된 일정 요약을 다시 전달할 수 있다. 개인 일정은 과거 연결값이 남아 있어도 요약에서 제외한다. ID 없이 이름만 저장된 일정은 동명 프로젝트가 여러 개면 자동 연결하지 않는다.

견적·고객 번호가 있는 프로젝트에 일정을 연결해 저장하면 두 번호도 연결 기준으로 기억한다. 이후 프로젝트 번호가 같아도 견적·고객이 다른 프로젝트에는 이전 일정을 요약으로 전달하지 않는다. 이름만 바뀌고 견적·고객이 같은 경우에는 연결을 유지한다. 이전에 저장한 일정처럼 연결 기준이 없는 자료는 기존 ID·이름 연결을 유지하므로 전체 초기화 전 별도 확인이 필요하다. 이 보완은 전체 초기화 시 일정 삭제나 프로젝트 삭제 차단을 대신하지 않는다.

## 19. 11월 9일 화면 검증

원본 데이터와 분리한 로컬 테스트 주소에서 기본 일정 등록·수정·완료·즐겨찾기, 월말 반복의 2월 28일·3월 31일 표시와 한 회차 수정 후 다른 회차 유지를 확인했다. 한 회차 삭제·되돌리기 후 새로고침 유지와 전체 반복 삭제도 확인했다. 전체 반복 삭제 후 되돌리기는 자동 테스트로 확인했으며 실제 브라우저에서의 연속 조작은 확인창 제어 지연으로 확정하지 않았다.

375px의 일별·주별·담당자별 주간·월별 보기에서 페이지 전체 가로 넘침이 없었다. 일정 입력창의 Tab 순환·Escape 닫기·초점 복귀를 확인했다. 상단바가 입력창 제목·닫기 버튼을 가리던 문제는 일정 팝업의 z-index를 높여 수정하고 같은 너비에서 재확인했다. 이는 테스트한 빌드의 관찰 결과이며 모든 기기·조합을 보장하는 것은 아니다.
