# 일정관리 공통 영역 조정 요청

작성일: 2026-11-10

## 5번에서 완료한 보호

- 프로젝트 연동 실패 시 일정 원본을 유지하고 대상 프로젝트·실패 사유를 안내한다.
- ‘프로젝트 연동 다시 시도’로 마지막 저장 성공 목록의 요약을 다시 전달한다.
- 개인 일정은 과거 연결값이 남아 있어도 프로젝트 요약에서 제외한다.
- 이름만 있는 일정은 동명 프로젝트가 여러 개면 자동으로 요약에 포함하지 않는다.
- 새로 저장하는 연결은 견적·고객 번호를 기억한다. 프로젝트 ID가 같아도 이 기준이 달라지면 다른 프로젝트에 요약을 전달하지 않는다. 기준이 없는 과거 자료나 같은 견적·고객 번호까지 재사용한 경우를 완전히 구분하지는 못한다.

## 공통 담당자와 조정할 내용

| 순서 | 파일 | 요청 사항 | 완료 확인 기준 |
| --- | --- | --- | --- |
| 1 | `src/context/ERPContext.js`, `src/components/Sidebar.js` | 전체 초기화에 일정·팀원·제외 팀원·초안을 포함할지 확정하고, 실제 범위를 버튼 문구에 반영한다. 모듈별 실패 결과도 확인한다. | 초기화 직후와 새로고침 뒤 결과가 같고, 이전 일정이 재사용된 프로젝트 ID에 연결되지 않는다. |
| 2 | `src/context/ERPContext.js`의 `deleteProject` | 연결 일정이 있으면 삭제 차단·연결 해제·함께 삭제 중 하나로 통일한다. 단순한 첫 구현은 삭제 차단을 권장한다. | 연결 일정이 있는 프로젝트의 삭제가 정한 규칙을 따르고, 실패 시 성공 화면으로 이동하지 않는다. |
| 3 | `src/context/ERPContext.js`, `src/context/useProjectData.js` | 일정 요약 전용 갱신을 일반 프로젝트 정보 수정과 분리한다. 저장 실패를 호출자에게 반환한다. | 요약 갱신에 무관한 담당자·작업 기간 오류로 거절되지 않고, 저장 실패 시 성공을 반환하지 않는다. |
| 4 | `src/3_projects/ProjectDetail.js`의 이력 표시, 필요 시 `src/context/useProjectData.js` | `schedules`와 `[object Object]`를 사람이 읽을 수 있는 연결 일정 이름·건수로 표시한다. | 일정 추가·수정·삭제 이력에서 변경 내용을 구별할 수 있다. |

1번 적용 시 5번의 `scheduleStorage.js`와 `scheduleHooks.js`도 함께 연결해야 한다. 저장 키만 지우면 열린 일정 화면의 자동 저장이 이전 자료를 다시 기록할 수 있으므로 화면 상태·작성 초안도 함께 갱신해야 한다. 다른 탭의 미저장 내용 처리도 정해야 한다.

일정 저장 키는 `made-mate-schedules`, `made-mate-schedule-team`, `made-mate-excluded-team`이며, 작성 초안은 sessionStorage의 `made-mate-schedule-draft`이다. `made-mate-schedules-backup-*` 백업의 초기화 포함 여부도 별도로 결정한다. 다른 탭의 sessionStorage는 현재 탭에서 직접 초기화할 수 없으므로 탭별 알림 처리가 필요하다.

과거 일정의 연결 기준이 없으면 새 프로젝트에 무조건 기준을 채우는 방식으로 이관하지 않는다. 기존 연결의 신뢰성을 확인하거나 사용자가 프로젝트를 다시 선택하는 절차를 정한다.

## 확인 범위

- 실제 Chrome: 기존 일정 11건, 정상 저장 상태, 개인 일정 상세·편집 화면의 프로젝트 연결 항목 없음 확인. 이번 확인에서 일정 등록·수정·삭제는 실행하지 않았다.
- 자동 테스트: 프로젝트 갱신의 실패 반환·예외, 프로젝트명과 사유 표시, 재시도 호출, 성공 반환 후 안내 해제, 동명 프로젝트의 이름 기반 연결 제외, ID 지정 연결 유지, 개인 일정의 과거 연결 제외를 검사한다.
- 실제 브라우저에서 실패 후 재시도와 동명 프로젝트 예외 조건은 재현하지 않았다. 공통 Provider의 실제 저장 완료까지 보장하는 검사는 별도로 필요하다. 재시도 안내 해제는 현재 갱신 함수의 성공 반환을 기준으로 한다.
- 이 문서는 전달용 정리이며 메시지 전송이나 공통 파일 수정은 실행하지 않았다.
